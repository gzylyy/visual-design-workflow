# 项目视觉规范

每个项目单独维护 visual-spec.md，记录下面的已确定值与未知项。未涉及角色或字体的纯图像任务写“不适用”，避免伪造需求。

| 字段 | 要记录的决定 |
|---|---|
| 项目 | ID、主题、用途、受众、当前版本 |
| 风格 | 媒介、抽象/写实程度、关键参考 ID 与选用属性 |
| 色彩 | 主辅色、强调色、背景/文字对比、色彩空间 |
| 材质 | 表面粗糙度、纹理密度、金属/纸张等表现 |
| 光影 | 主光方向、软硬、色温、阴影与接触关系 |
| 线条 | 粗细相对尺度、轮廓、边缘与笔触特征 |
| 构图 | 网格、边距、视觉焦点、视角、比例与裁切 |
| 主体 | 角色或产品的识别特征、参考母版 |
| 字体 | 字族与字重、授权/可用状态、替代字体、层级 |
| 保留项 | 必须保持、禁止新增、允许变化与资产作用域 |
| 输出 | 尺寸、格式、透明背景、路径、命名及源文件 |

先明确用户已锁定的内容，再设置其余参数。不得把“风格统一”解释成所有任务只能用同一套颜色或画法。科技、文化、美食等主题只是内容选项，不是固定的风格分类。

颜色和字体应在目标平台预览。RGB 屏幕颜色不能直接当作印刷承诺；字体缺失时记录替换结果，不能默默替换导致溢出。将文字转曲可保形但丢失文字编辑能力，按用户目标同时保留活字版本。

将规范分成项目全局、系列、资产局部三级。修改一张图的色温只更新局部覆盖；只有用户要求全系列变更才修改全局基准。保留旧版本和原因，用版本号绑定导出文件。
